# 02 — devices

## რას ვაკეთებთ

ვინახავთ ყოველ დაყენებულ აპს: `device_id`, პლატფორმა, ენა, აპის ვერსია და ბოლო ნახვის დრო. FCM token ცალკე `fcm_tokens` ცხრილში ინახება და `device_id`-ით უკავშირდება მოწყობილობას. ლოკაციის გაზიარება და ბოლო კოორდინატები ცალკე `location_settings` ცხრილშია.

## როგორ

`device_id` აპი გზავნის (uuid). სერვერი მას არ გამოიმუშავებს.

`POST /devices/` არის upsert იმავე `device_id`-ზე:

- ახალი მოწყობილობა იწერება `created_at = now()`, `last_seen_at = now()`.
- უკვე არსებული მოწყობილობის `last_seen_at` ყოველ ამ მოთხოვნაზე ახლდება. `created_at` აღარ იცვლება.
- `platform`, `language`, `app_version` მოდის device მოთხოვნიდან. FCM token ცალკე endpoint-ით რეგისტრირდება.

ერთ მოწყობილობას მხოლოდ ერთი აქტიური FCM token აქვს. ახალი token-ის რეგისტრაცია ძველს შლის. ერთი token ორ მოწყობილობას ვერ ეკუთვნის; ახალ მოწყობილობაზე რეგისტრაციისას ის ახალ device-ზე გადადის.

`last_seen_at`-ით მოგვიანებით იწმინდება მოწყობილობა, რომელიც დიდი ხანია აღარ გამოჩენილა. წაშლის წესი (რამდენი დღე) ცალკე დავაფიქსიროთ, სანამ გაწმენდის სამუშაოს დავიწყებთ. წაშლა `alert_settings`-ს, `fcm_tokens`-ს, `notification_outbox`-ს და `felt_reports`-ს თან წაიღებს (`ON DELETE CASCADE`).

## მზადაა, როცა

იგივე `device_id`-ზე მეორე device POST ახალ სტრიქონს არ ქმნის და `last_seen_at`-ს ანახლებს. FCM token იწერება `/devices/{device_id}/fcm-tokens/`-ით და წაიშლება DELETE-ით.
