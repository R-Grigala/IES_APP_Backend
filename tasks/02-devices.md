# 02 — devices

## რას ვაკეთებთ

ვინახავთ ყოველ დაყენებულ აპს: `device_id`, პლატფორმა, ენა, აპის ვერსია და ბოლო ნახვის დრო. FCM token-ები ცალკე `fcm_tokens` ცხრილში ინახება და `device_id`-ით უკავშირდება მოწყობილობას. ლოკაციის გაზიარება და ბოლო კოორდინატები ცალკე `location_settings` ცხრილშია.

## როგორ

`device_id` აპი გზავნის (uuid). სერვერი მას არ გამოიმუშავებს.

`POST /devices/` არის upsert იმავე `device_id`-ზე:

- ახალი მოწყობილობა იწერება `created_at = now()`, `last_seen_at = now()`.
- უკვე არსებული მოწყობილობის `last_seen_at` ყოველ ამ მოთხოვნაზე ახლდება. `created_at` აღარ იცვლება.
- `fcm_token`, შეტყობინებების ნებართვა, `platform`, `language`, `app_version` მოდის იმავე მოთხოვნიდან.

ერთ მოწყობილობას შეიძლება რამდენიმე FCM token ჰქონდეს. თითოეული token უნიკალურია, ინახავს `notifications_enabled`, `created_at` და `updated_at` მნიშვნელობებს. ერთი token ორ მოწყობილობას ვერ ეკუთვნის; ახალ მოწყობილობაზე რეგისტრაციისას ძველ მოწყობილობას ჩამოერთმევა.

`last_seen_at`-ით მოგვიანებით იწმინდება მოწყობილობა, რომელიც დიდი ხანია აღარ გამოჩენილა. წაშლის წესი (რამდენი დღე) ცალკე დავაფიქსიროთ, სანამ გაწმენდის სამუშაოს დავიწყებთ. წაშლა `alert_settings`-ს და `notifications_sent`-ს თან წაიღებს (`ON DELETE CASCADE`). `felt_reports` დარჩება, `device_id` გახდება `NULL`.

## მზადაა, როცა

იგივე `device_id`-ზე მეორე `POST` ახალ სტრიქონს არ ქმნის, `last_seen_at`-ს ანახლებს, და `NULL` ტოკენი მიიღება.
